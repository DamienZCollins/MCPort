# MCP 工具服务 + 调度网关 - 开发路径

## 阶段总览

| 阶段 | 主题 | 产物 |
|------|------|------|
| 0 | 仓库与本地环境 | 可一键启动的 MySQL + Redis、提交与编码规范 |
| 1 | 基础设施 + 核心框架 | 可启动服务、建表与合成数据、MCP Server 集成验证 |

| 4 | 客户端兼容 + 交付 | Java Client、MCP Inspector、API 文档与实测数据 |

按阶段顺序推进，每个阶段结束都有可运行产物；阶段内任务不绑定工期。

## 阶段 2：工具层实现

### 目标
实现 6 个 MCP 工具，对接真实业务逻辑（MySQL 查询/更新）。

### 任务清单

#### 只读工具实现（READ 权限）
- [x] `query_orders` - 查询订单列表
  - 输入：`userId`（必填）、`status`（可选）、`limit`（可选，默认 10，最大 100）
  - 输出：`List<OrderView>`
  - 逻辑：`SELECT * FROM t_order WHERE user_id = ? [AND status = ?] ORDER BY created_at DESC LIMIT ?`
- [x] `check_inventory` - 查询库存
  - 输入：`skuId`（必填）、`warehouseId`（可选）
  - 输出：`InventoryInfo{skuId, warehouseId, availableQty, reservedQty}`
  - 逻辑：`SELECT * FROM t_inventory WHERE sku_id = ? [AND warehouse_id = ?]`
- [x] `get_order_detail` - 订单详情
  - 输入：`orderId`（必填）
  - 输出：`OrderDetail{order, items}`
  - 逻辑：关联查询 `t_order` + `t_order_item`

**代码示例**（`mcport-server/src/main/java/com/mcport/tool/OrderTools.java`）
```java
@McpTool(name = "query_orders", description = "查询用户订单列表，支持按状态过滤",
        annotations = @McpTool.McpAnnotations(readOnlyHint = true, destructiveHint = false,
                idempotentHint = true, openWorldHint = false))
public List<OrderView> queryOrders(
        @McpToolParam(description = "用户 ID", required = true) String userId,
        @McpToolParam(description = "订单状态：PENDING/PAID/SHIPPED/COMPLETED，留空返回全部", required = false)
        String status,
        @McpToolParam(description = "返回记录数，默认 10，最大 100", required = false) Integer limit) {
    // 校验 + 规范化后交给 service；越界 limit 直接拒绝，不静默截断
    ...
}
```

#### 写入工具实现（WRITE 权限）
- [x] `update_order_status` - 更新订单状态
  - 输入：`orderId`（必填）、`newStatus`（必填）、`remark`（可选）
  - 输出：`UpdateResult{success, orderId, oldStatus, newStatus}`
  - 逻辑：`UPDATE t_order SET status = ? WHERE order_id = ?`
  - 操作审计在阶段 3 由治理切面统一记录
- [x] `lock_inventory` - 锁定库存
  - 输入：`skuId`（必填）、`quantity`（必填）、`orderId`（必填）
  - 输出：`LockResult{success, orderId, skuId, lockedQty, remainingQty, idempotent}`
  - 逻辑：`UPDATE t_inventory SET available_qty = available_qty - ?, reserved_qty = reserved_qty + ? WHERE sku_id = ? AND available_qty >= ?`
  - 幂等性控制：`t_inventory_lock` 以 `(order_id, sku_id)` 唯一约束兜底，重复调用返回首次结果

#### 可选工具 - 知识库检索
- [x] `search_knowledge` - 知识库检索（ES 可选）
  - 输入：`query`（必填）、`category`（可选）
  - 输出：`List<Document>{id, title, content, category, score}`
  - 一期实现：返回 Mock 数据（3 篇固定文档）
  - 二期优化：接入真实 Elasticsearch

#### 单元测试 + 工具联调
- [x] 为每个工具编写单元测试
  - 测试正常路径
  - 测试边界条件（limit 超限、status 非法值）
- [x] 用 curl 测试所有工具（握手、`tools/list`、`tools/call` 命令见 [API.md](API.md)）

**口径说明**

- 工具参数名由 MCP 注解扫描器取**方法形参名**（camelCase），不是 `@McpToolParam` 的字段；因此工具形参一律用 camelCase，调用方按 `tools/list` 的 `inputSchema` 传参。改用 `@JsonProperty` 重命名不起作用
- `@McpToolParam.required` 默认 `true`，可空参数必须显式写 `required = false`，否则会被列入 schema 的 `required`
- 锁定库存的幂等由 `t_inventory_lock` 的 `(order_id, sku_id)` 唯一约束保证；重复调用直接返回首次结果，不再扣减

#### AOP 权限校验 + 限流
- [ ] 创建 `McpToolGovernanceAspect`
  ```java
  @Aspect
  @Component
  public class McpToolGovernanceAspect {
      @Around("@annotation(org.springframework.ai.mcp.server.McpTool)")
      public Object govern(ProceedingJoinPoint pjp) throws Throwable {
          // 1. 获取 API Key 上下文
          ApiKeyContext context = ApiKeyContext.get();
          
          // 2. 权限检查
          String toolName = extractToolName(pjp);
          String requiredPermission = getToolPermission(toolName);
          if (!context.hasPermission(requiredPermission)) {
              throw new ForbiddenException("Tool requires " + requiredPermission);
          }
          
          // 3. 限流
          rateLimiter.checkLimit(context.getApiKey(), context.getRateLimit());
          
          // 4. 执行工具
          return pjp.proceed();
      }
  }
  ```
- [ ] 创建 `RedisRateLimiter`
  ```java
  public void checkLimit(String apiKey, int limitPerMinute) {
      String key = "limit:" + apiKey + ":" + (System.currentTimeMillis() / 60000);
      Long count = redisTemplate.opsForValue().increment(key);
      if (count == 1) redisTemplate.expire(key, 60, TimeUnit.SECONDS);
      if (count > limitPerMinute) throw new RateLimitException();
  }
  ```
- [ ] 测试权限校验

- [ ] 创建 `OwnershipValidator`
  ```java
  @Component
  public class OwnershipValidator {
      public void checkOrderOwnership(String orderId, String currentUserId) {
          Order order = orderMapper.selectById(orderId);
          if (order == null) throw new NotFoundException("Order not found");
          if (!order.getUserId().equals(currentUserId)) {
              auditService.logBlock("UNAUTHORIZED_ACCESS", orderId);
              throw new ForbiddenException("Cannot access other user's order");
          }
      }
  }
  ```
- [ ] 在工具方法中调用校验

      ownershipValidator.checkOrderOwnership(orderId, currentUserId);
      return orderService.getDetail(orderId);
  }

## 明确不做

以下功能不在本项目范围内：

1. **多租户计费系统**：单用户或信任团队场景，不做复杂的多租户隔离和计费
2. **K8s 部署与服务网格**：Docker Compose 足够，不做云原生复杂部署
3. **OAuth 完整流程**：简化为 API Key 鉴权，不做 OAuth2 授权码/隐式/密码模式
4. **向量数据库/RAG 完整链路**：Elasticsearch 可选，不做向量化检索
5. **工具动态注册**：工具清单在启动时固定，不做运行时动态注册
6. **Prompt 管理仓库**：不做中心化 Prompt 版本控制
7. **生产监控和告警**：只做离线指标采集，不做实时告警
8. **复杂的团队协作**：不做审批流、权限树、角色管理
9. **通用可观测平台对接**：不对接 Datadog、Grafana 等第三方平台
10. **Claude Desktop 桥接进程**：其配置文件只支持 stdio，需额外开发桥接，不作为一期目标

## 分支与提交策略

### 分支命名
```
main              # 主分支，保护分支
develop           # 开发分支
feature/xxx       # 功能分支（从 develop 切出）
fix/xxx           # 修复分支
```

### 提交规范
遵循 `AGENTS.md` 中的 commit message 格式：

```
<type>: <精炼描述>

type 取值：
- feat：新增功能
- fix：修复 bug
- refactor：重构
- perf：性能优化
- docs：文档
- test：测试
- build：构建、依赖
- chore：杂项
```

### 提交粒度
- 每次提交控制在 50 行左右，便于 review
- 搭建骨架、文档、引入依赖等无法拆分的提交除外

### 示例
```bash
git commit -m "feat: 实现 query_orders 工具"
git commit -m "feat: 添加 API Key 鉴权过滤器"
git commit -m "feat: 实现 Redis 滑动窗口限流"
git commit -m "fix: 修复越权检查中管理员判断逻辑"
git commit -m "docs: 补充客户端接入指南"
```

## 每阶段工作流

1. **开工**：确认本阶段任务清单与验收标准，拉起本地环境（`docker compose up -d`）
2. **实现**：按任务清单顺序推进，每个能力先落目录再写实现（见 `编码约定.md`）
3. **验证**：跑本阶段的验收命令（curl / 单测 / 集成测试），结果记入阶段交付物
4. **收尾**：更新 `README.md` 的当前进度与 `docs/`，按提交规范分批提交
