# 编码约定

## 目录即架构

分包按「职责层」组织，目录结构直接反映依赖方向：

```text
mcport-server/
└── com.mcport
    ├── api/          # MCP 端点与接入层：协议接入、参数校验、返回封装
    ├── tool/         # 工具层：@McpTool 方法，只写业务编排
    ├── governance/   # 治理层：横切能力，环绕工具调用
    │   ├── aspect/   # 治理切面（鉴权 → 权限 → 限流 → 审计 → 指标）
    │   ├── auth/     # API Key 鉴权与上下文
    │   ├── ratelimit/# 限流
    │   ├── audit/    # 审计日志
    │   └── validator/# 越权与参数校验
    ├── service/      # 业务逻辑
    ├── mapper/       # MyBatis-Plus Mapper
    ├── entity/       # 数据库实体
    └── dto/          # 工具输入输出与接口返回体
```

依赖方向单向：`api / tool → governance → service → mapper`。`service` 不依赖 `tool` 与 `api`；工具层不直接写 SQL。新增能力先决定落在哪层，再建包。

## 命名

| 类型 | 规则 | 示例 |
|------|------|------|
| 实体 | 表名去 `t_` 后单数驼峰 | `t_order` → `Order` |
| Mapper | 实体名 + `Mapper` | `OrderMapper` |
| Service | 业务名 + `Service` | `OrderService` |
| 工具类 | 业务域 + `Tools` | `OrderTools` |
| 工具方法 | `@McpTool(name = "snake_case")` | `query_orders` |
| DTO | 用途后缀 | `OrderDetail`、`LockResult` |
| 枚举 | 全大写下划线 | `OrderStatus.PAID` |

- 表名统一 `t_` 前缀
- 时间字段统一 `created_at` / `updated_at`
- 布尔字段用 `enabled` 形式，`TINYINT(1)` 存储

## 数据库

- 字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`，时区 `+08:00`
- 唯一约束显式命名：`uk_{表名}_{字段}`；普通索引：`idx_{表名}_{字段}`
- 表结构以 SQL 脚本管理：`docker/init/01-schema.sql` 建表、`02-data.sql` 合成数据；不手改库
- 所有查询经由 MyBatis-Plus 参数化（`#{}`），不拼 SQL 字符串

## 接口与错误

- MCP 端点固定 `POST /mcp`（Streamable HTTP），请求头 `Authorization: Bearer <api_key>`
- 工具入参用 `@McpToolParam` 描述，必填项显式标注；数量上限在工具方法内收敛（如 `limit` 最大 100）
- 错误码：401 未鉴权 / 403 权限不足或越权 / 429 限流，错误体统一 `{error, message}`
- 治理层抛出的异常不吞掉，交由 MCP Server 转换为协议错误

## 配置

- 敏感信息只走环境变量，配置文件中用 `${VAR:default}` 占位
- 新增环境变量必须同步更新 `.env.example` 与 `docker/.env.example`
- 本地覆盖用 `application-local.yml`，不提交
