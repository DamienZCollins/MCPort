# MCP 工具服务 + 调度网关 - 总体方案

## 项目定位

### 核心价值
一个生产级 MCP 工具服务 + 治理层网关，展示 API 网关治理能力和 MCP 协议集成能力。

**做什么**：
- 工具层：用真实业务逻辑实现 6 个 MCP 工具（只读为主 + 写入分离）
- 治理层：完整的调度治理能力（鉴权、权限分级、限流、审计、安全防护），以 AOP 切面形式环绕工具调用
- 可观测性：从第一行代码起预埋指标采集点，输出量化数据

**明确不做**：
- ❌ 多租户计费系统（超出单人项目范围）
- ❌ K8s 部署与服务网格（Docker Compose 够用）
- ❌ OAuth 完整流程（简化为 API Key 鉴权）
- ❌ 跨语言 SDK 适配（只验证 Java + 2 个现成客户端）
- ❌ 向量数据库/RAG 完整链路（Elasticsearch 降为可选组件）
- ❌ 工具动态注册（工具清单在启动时固定）


## 领域建模

### 核心对象

**1. MCP Tool（工具）**
```
工具是 Agent 可调用的原子能力单元
- 只读工具（READ 权限）：query_orders、check_inventory、get_order_detail、search_knowledge
- 写入工具（WRITE 权限）：update_order_status、lock_inventory
```

**2. API Key（调用凭证）**
```
每个 API Key 携带：
- user_id（所属用户）
- permissions（权限列表：["READ", "WRITE"]）
- rate_limit_per_minute（QPM 限制）
- enabled（是否启用）
```

**3. Audit Log（审计日志）**
```
记录每次工具调用：
- 谁调用（api_key + user_id）
- 调用了什么（tool_name + input_params）
- 结果如何（status + output_summary + latency_ms）
- 是否被拦截（block_reason）
```

**4. Governance Aspect（治理切面）**
```
环绕工具调用的治理逻辑：
1. 鉴权 → 2. 权限校验 → 3. 限流 → 4. 参数校验 → 5. 执行 → 6. 审计 → 7. 指标
```

### 状态流转

**API Key 状态**
```
ENABLED（启用）→ 调用成功
             → 超过限流 → 返回 429
             → 权限不足 → 返回 403
DISABLED（禁用）→ 返回 403
```

**工具调用流程**
```
请求到达 → 鉴权（401/403） → 权限校验（403） → 限流（429） 
→ 参数校验（越权检测，403） → 执行工具 → 记录审计日志 → 返回结果
```

### 模块职责说明

**`api.mcp`**：MCP Server 端点，处理 Streamable HTTP 请求，由 Spring AI Starter 自动注册。

**`tool`**：工具执行层，每个类用 `@Component` + `@McpTool` 注解，实现具体业务逻辑。

**`governance.aspect`**：治理切面，用 `@Around("@annotation(McpTool)")` 拦截所有工具调用，执行治理逻辑。

**`governance.auth`**：鉴权模块，从请求头提取 API Key，查询 Redis/MySQL，注入用户上下文到 ThreadLocal。

**`governance.ratelimit`**：限流模块，基于 Redis INCR + TTL 实现滑动窗口限流。

**`governance.audit`**：审计模块，用 `@Async` + 线程池异步写入 MySQL。

**`governance.validator`**：参数校验模块，检查越权访问（用户 A 查询用户 B 的订单）。

**`service`**：业务逻辑层，工具层调用 service 完成数据库操作。

**`mapper`**：MyBatis-Plus Mapper，直接操作数据库。

**1. `t_api_key` - API Key 管理表**

```sql
    user_id VARCHAR(32) NOT NULL COMMENT '用户 ID',
    permissions JSON NOT NULL COMMENT '权限列表，例如 ["READ", "WRITE"]',
    rate_limit_per_minute INT DEFAULT 60 COMMENT '每分钟调用次数限制',
    enabled TINYINT(1) DEFAULT 1 COMMENT '是否启用：1-启用，0-禁用',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id)
) COMMENT 'API Key 管理表';
```

**2. `t_audit_log` - 审计日志表**
```sql
CREATE TABLE t_audit_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    request_id VARCHAR(36) NOT NULL COMMENT 'UUID，关联请求链路',
    api_key VARCHAR(64) NOT NULL COMMENT 'API Key',
    user_id VARCHAR(32) NOT NULL COMMENT '用户 ID',
    tool_name VARCHAR(64) NOT NULL COMMENT '调用的工具名',
    input_params JSON COMMENT '输入参数（脱敏后）',
    output_summary VARCHAR(512) COMMENT '输出摘要（不存完整返回）',

    block_reason VARCHAR(128) COMMENT '拦截原因：RATE_LIMIT / FORBIDDEN / INVALID_PARAM / UNAUTHORIZED',
    error_message VARCHAR(512) COMMENT '错误信息',
    latency_ms INT NOT NULL COMMENT '执行耗时（毫秒）',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_time (user_id, created_at),
    INDEX idx_tool (tool_name),
    INDEX idx_status (status)
```

## 工具清单

| 工具名称 | 输入 | 输出 | 类型 | 权限 | 真实逻辑 |
|---------|------|------|------|------|---------|
| `query_orders` | `user_id`, `status?`, `limit?` | `List<Order>` | 只读 | READ | 查 MySQL `t_order` 表，越权检查 |
| `check_inventory` | `sku_id`, `warehouse_id?` | `InventoryInfo` | 只读 | READ | 查 MySQL `t_inventory` 表 |
| `get_order_detail` | `order_id` | `OrderDetail` | 只读 | READ | 关联查询 `t_order` + `t_order_item`，越权检查 |
| `search_knowledge` | `query`, `category?` | `List<Document>` | 只读（可选） | READ | ES match query 或 Mock 数据 |
| `update_order_status` | `order_id`, `new_status`, `remark?` | `UpdateResult` | 写入 | WRITE | 更新 `t_order.status`，越权检查，记操作日志 |
| `lock_inventory` | `sku_id`, `quantity`, `order_id` | `LockResult` | 写入 | WRITE | 扣减 `t_inventory.available_qty`，幂等性控制 |

### 实现示例

```java
@Component
public class OrderTools {
    
    @Autowired
    private OrderService orderService;
    
    @McpTool(
        name = "query_orders",
        description = "查询用户订单列表，支持按状态过滤"
    )
    public List<Order> queryOrders(
        @McpToolParam(description = "用户 ID", required = true) String userId,
        @McpToolParam(description = "订单状态：PENDING/PAID/SHIPPED/COMPLETED") String status,
        @McpToolParam(description = "返回记录数，默认 10，最大 100") Integer limit
    ) {
        // AOP 切面会在此方法执行前做鉴权、限流、越权检查
        // 此处只写业务逻辑
        if (limit == null) limit = 10;
        if (limit > 100) limit = 100;
        return orderService.queryByUser(userId, status, limit);
    }
    
    @McpTool(
        name = "update_order_status",
        description = "更新订单状态（需要 WRITE 权限）"
    )
    public UpdateResult updateOrderStatus(
        @McpToolParam(description = "订单 ID", required = true) String orderId,
        @McpToolParam(description = "新状态：PAID/SHIPPED/COMPLETED", required = true) String newStatus,
        @McpToolParam(description = "备注") String remark
    ) {
        // 治理层会检查 API Key 是否有 WRITE 权限
        return orderService.updateStatus(orderId, newStatus, remark);
    }
}
```

### 权限级别规则
- **READ**：所有 API Key 默认拥有（只读工具）
- **WRITE**：需管理员在数据库手动授予（写入工具默认禁用）


## 治理层设计

### 1. 鉴权方式

**API Key 认证流程**
```
请求头：Authorization: Bearer <api_key>

校验流程：
1. 从 Redis 查 api_key:{key} -> {user_id, permissions[], rate_limit, enabled}
2. 不存在 → 查 MySQL t_api_key 表 → 写回 Redis（TTL 1 小时）
3. 不存在 → 401 Unauthorized
4. enabled=false → 403 Forbidden
5. 验证通过 → 注入 ApiKeyContext{userId, permissions} 到 ThreadLocal
```

### 2. 权限分级规则

**⚠️ 工具可见性过滤实现说明**

`tools/list` 接口按权限过滤工具列表**不能通过工具方法的 AOP 切面实现**（AOP 只在工具调用时生效）。

**实现方案选择：一期只做调用时拦截**
- `tools/list` 返回所有工具（不过滤）
- 只在 `tools/call` 时通过 AOP 切面校验权限，无权限返回 403
- 客户端能看到工具列表，但调用时会被拦截

**AOP 实现**：
```java
@Aspect
@Component
public class McpToolGovernanceAspect {
    
    @Around("@annotation(org.springframework.ai.mcp.server.McpTool)")
    public Object govern(ProceedingJoinPoint pjp) throws Throwable {
        String toolName = extractToolName(pjp);
        String apiKey = extractApiKey();
        long start = System.currentTimeMillis();
        
        try {
            // 1. 鉴权
            ApiKeyContext context = authService.authenticate(apiKey);
            
            // 2. 权限检查（工具调用时拦截）
            String requiredPermission = getToolPermission(toolName);
            if (!context.hasPermission(requiredPermission)) {
                throw new ForbiddenException("Tool requires " + requiredPermission);
            }
            
            // 3. 限流
            rateLimiter.checkLimit(apiKey, context.getRateLimit());
            
            // 4. 参数校验
            validateParams(toolName, pjp.getArgs(), context.getUserId());
            
            // 5. 执行工具
            Object result = pjp.proceed();
            
            // 6. 异步审计
            long latency = System.currentTimeMillis() - start;
            auditService.logSuccess(toolName, apiKey, context.getUserId(), 
                                    pjp.getArgs(), result, latency);
            
            // 7. 指标
            metrics.recordSuccess(toolName, latency);
            
            return result;
            
        } catch (Exception e) {
            auditService.logFailure(toolName, apiKey, e);
            metrics.recordFailure(toolName, e.getClass().getSimpleName());
            throw e;
        }
    }
}
```

### 3. 限流策略

**Redis 滑动窗口限流**
```java
@Service
public class RedisRateLimiter {
    
    public void checkLimit(String apiKey, int limitPerMinute) {
        String key = "limit:" + apiKey + ":" + (System.currentTimeMillis() / 60000);
        Long count = redisTemplate.opsForValue().increment(key);
        
        if (count == 1) {
            redisTemplate.expire(key, 60, TimeUnit.SECONDS);
        }
        
        if (count > limitPerMinute) {
            throw new RateLimitException("Rate limit exceeded: " + limitPerMinute + "/min");
        }
    }
}
```

**限流配置**：
- 每个 API Key 有独立的 `rate_limit_per_minute` 配置（存在 `t_api_key` 表）
- 默认限制 60 QPM，管理员可调整

### 4. 审计日志

**写入策略**：
- 使用 Spring 的 `@Async` + 线程池异步写入 MySQL
- 直接写入数据库，无需 Redis 缓冲（简化架构）

**记录字段**：
- 请求标识（request_id、api_key、user_id）
- 调用信息（tool_name、input_params、output_summary）
- 执行结果（status、block_reason、error_message、latency_ms）
- 时间戳（created_at）

### 5. 参数校验与安全防护

**SQL 注入防护**
- MyBatis-Plus 参数化查询（`#{param}`），框架层面防注入
- 不提供通用 SQL 执行工具，只暴露固定业务查询

**越权防护**
```java
@Component
public class OwnershipValidator {
    
    public void checkOrderOwnership(String orderId, String currentUserId) {
        Order order = orderMapper.selectById(orderId);
        if (order == null) {
            throw new NotFoundException("Order not found");
        }
        if (!order.getUserId().equals(currentUserId) && !isAdmin(currentUserId)) {
            auditService.logBlock("UNAUTHORIZED_ACCESS", orderId);
            throw new ForbiddenException("Cannot access other user's order");
        }
    }
}
```

**在工具层调用**：
```java
@McpTool(name = "get_order_detail")
public OrderDetail getOrderDetail(@McpToolParam(...) String orderId) {
    String currentUserId = ApiKeyContext.getCurrentUserId(); // 从 ThreadLocal 获取
    ownershipValidator.checkOrderOwnership(orderId, currentUserId);
    return orderService.getDetail(orderId);
}
```

## 数据准备

### 合成数据规模
- **订单数据**：至少 1 万条（`t_order` + `t_order_item`）
- **库存数据**：500 个 SKU（`t_inventory`）
- **用户数据**：1000 个用户（订单分布在这些用户下）

### 数据生成方案

**使用 JavaFaker 库**
```java
Faker faker = new Faker(Locale.CHINA);
for (int i = 0; i < 10000; i++) {
    Order order = new Order();
    order.setOrderId("ORD" + System.currentTimeMillis() + i);
    order.setUserId("user" + (i % 1000)); // 1000 个用户
    order.setStatus(randomStatus());
    order.setTotalAmount(faker.number().randomDouble(2, 10, 5000));
    order.setCreatedAt(faker.date().past(365, TimeUnit.DAYS));
    orderMapper.insert(order);
}
```

导出为 SQL 文件：`docker/init/02-data.sql`


## 风险与取舍

### 风险 1：Spring Boot 3.5.x 兼容性
**缓解**：先用 3.4.1 验证，如 3.5.x 有冲突则回退

### 风险 2：客户端调试耗时
**取舍**：优先保证自研 Java Client，Inspector 调试超过 1 天则降级为 curl 测试

### 风险 3：Elasticsearch 资源占用
**取舍**：阶段 1-3 不启动 ES，`search_knowledge` 返回 Mock 数据，阶段 4 有余力再接入

### 风险 4：第三个客户端兼容性
**降级**：只测 2 个客户端（自研 Java Client + MCP Inspector）

### 最可能砍掉的功能
- Elasticsearch 知识库检索（剩余 5 个工具仍满足需求）
- 第三个客户端兼容测试
- `tools/list` 按权限过滤（一期只做调用时拦截）
